Current data flow and routing
artifacts/lille-nest/src/App.tsx:38-60 is the sole router. It routes /products to the listing, /products/:slug to product detail, and /blog plus /blog/:slug to bespoke editorial pages. There is no catalog CMS-page route; unmatched paths go to NotFound (:60).
artifacts/lille-nest/src/data/products.ts:1-22 is the only importer/consumer of src/data/jacadi-catalog.json: it casts the JSON to JacadiCatalog, exports catalog.products, maps catalog.categories, and provides a few product helpers. No app component reads catalog.home or catalog.pages.
Data inspected: 948 products, 176 categories, and 17 SourcePages (including home as a separate field). Products reference 28 category slugs; the JSON’s counts agree with product membership, but 148 categories have zero products. Every catalog product has an empty images array; every source page has empty images too.
Product/category rendering and breaks
Product consumers: pages/Products.tsx:6-7,27-52,223-225 filters/maps all exported products; pages/Search.tsx:8,14-23,67-71 searches/maps them; pages/ProductDetail.tsx:15,27 finds a product by slug; Wishlist.tsx:9,14,52-55 displays the first three; RelatedProducts.tsx:3,11-17,28-30 derives related products. Home consumes getFeaturedProducts() in components/home/FeaturedProductsSection.tsx:3,12-14,31-34; categories are shown by CategoriesSection.tsx:1,17-20 and CategoryCard.tsx:10-18 links to /products?category=<slug>.
Missing component: src/components/products/ProductCard.tsx does not exist, despite imports from listing, search, wishlist, related products, and home. This is a direct module-resolution/build blocker for the catalog surfaces.
Missing data helper: FeaturedProductsSection.tsx:3,12-14 imports/calls getProductsByAge, which is not exported by data/products.ts. ageFilters is explicitly empty (products.ts:11), so the age UI has no options; data has no age field to power it.
Featured selection hides all imported products: getFeaturedProducts() filters for non-empty images (products.ts:16-17), but all 948 have no images, so the home featured grid is empty. Category images are similarly derived from product.images[0] (products.ts:7-10) and thus all undefined; CategoryCard renders that missing image (CategoryCard.tsx:23-27). A fallback is required, not merely an image-selection change.
Detail view is incompatible with the JSON and will fail at runtime even after restoring ProductCard: catalog Product fields are only those in types/product.ts:1-17; there are no ageRange, stock, rating, reviewCount, isNew, isBestseller, or badges fields. Yet ProductInfo.tsx:12-32,48-56,77-96, ProductDetail.tsx:54-57,108-119,130-132, RelatedProducts.tsx:14-16, and Cart.tsx:82 assume them. In particular ProductInfo immediately reads product.ageRange; RelatedProducts compares missing age ranges; details/cart assume stock/reviews. Adapt those components to fields actually imported (availability, sizes, etc.) or supply explicit safe defaults; do not treat absent mock fields as real inventory/reviews.
ImageGallery.tsx:23-35 renders images[0] without an empty-array fallback, so catalog details have a broken image. Catalog availability is available as the stock-status source.
Listing currently maps all 948 products (Products.tsx:27-33,223-225), but the missing card prevents display. Product links use /products/:slug in detail context, while cart links incorrectly use /product/:slug (Cart.tsx:58,68), a path not registered in App.tsx.
Category/navigation mismatch: header/footer/hero hardcode toys, clothes, and books (Header.tsx:9-16, Footer.tsx:13-16, HeroSection.tsx:35-37); none is a category slug or has catalog products (all filter to zero). Use actual catalog category slugs. The listing’s sale filter works on originalPrice, but filter=new and filter=bestseller links are not implemented by Products.tsx (it only checks filter=sale, lines 14-15, 35-37). getNewArrivals/getBestsellers exist but are not used by those links.
CMS/editorial pages
/about, /faq, /shipping, /returns, /privacy, /terms, etc. route to independent hand-authored page components in App.tsx:48-58; for example About.tsx:7-10 uses bespoke data/content.ts, while Shipping.tsx, FAQ.tsx, Returns.tsx, Privacy.tsx, and Terms.tsx contain their own fixed text. These are not renderers for catalog SourcePages.
The separate /blog and /blog/:slug pages use hard-coded, mismatched mock article arrays in pages/Blog.tsx:12-75 and BlogPost.tsx:11-97; they do not render catalog pages either. SourcePage/ContentBlock types exist at types/product.ts:43-55, but no page component consumes them. The JSON contains 17 editorial/content pages (back-to-school, our-story, jacadi-stores, privacy-policy, etc.) that are currently unreachable as imported page data.
